## Key claims the report will draw on

- **Problem 2 is stated as a point-to-point problem, not single-source.** Dijkstra asks for "the path of minimum total length between two given nodes P and Q", and his loop terminates the moment Q enters set A. The single-source formulation the report uses is a (trivial) generalisation obtained by running the loop to exhaustion; the paper itself does not state it that way. (p. 270, Problem 2 and Step 2.)
- **The optimal-substructure argument is given explicitly and is the whole justification for the method.** (p. 270, first paragraph after Problem 2.)
- **Nodes enter the settled set in order of increasing distance.** Set A is defined as "the nodes for which the path of minimum length from P is known; nodes will be added to this set in order of increasing minimum path length from node P". This is the invariant the report's implementation relies on. (p. 270, set A.)
- **The extract-min step is specified only as "the node with minimum distance", with no data structure.** Step 2 says the minimum-distance node in set B is transferred to set A. Dijkstra names no container, no ordering discipline, and no way of finding that minimum other than by inspecting set B. The linear scan is what the text describes; nothing heap-like appears anywhere in the paper. (p. 270, Step 2.)
- **The relaxation step is Step 1 and is stated in exactly the modern form.** For each branch from the just-settled node to a node R in B, if the new path is shorter it replaces the incumbent branch in set II, otherwise it is rejected; if R is still in C it is moved to B. This is `if d(u) + w < d(v) then d(v) := d(u) + w`. (p. 270, Step 1.)
- **The paper contains no complexity analysis at all.** There is no asymptotic notation, no operation count, and no running-time bound anywhere in the three pages. The only efficiency claims are about *storage* (never more than n branches held simultaneously) and one informal remark that "the amount of work to be done seems to be considerably less" than Ford's method. The O(V²) figure universally attributed to "Dijkstra's algorithm" is a later analysis of the method Dijkstra described, not a result stated in this paper. (p. 271, final paragraph.)
- **Problem 1, on pp. 269–270, is the minimum spanning tree algorithm** now usually called Prim's (or Jarník's). The paper is two algorithms, and the shortest-path one is the second. The report should not cite "Dijkstra (1959)" as if the whole paper were about shortest paths.
- **The method is stated to work on directed graphs.** Remark 1: the process applies where branch length depends on direction of traversal. (p. 270, Remark 1.)
- **Only n − 1 stored branches at a time.** Remark 2 prescribes storing, per branch in sets I and II, its two endpoints and the distance from P — for set I the actual minimum, for set II "only the minimum thus far obtained". That is exactly a tentative-distance array with a predecessor pointer. (pp. 270–271, Remark 2.)

## Quotable sentences

All quotations below were read from the typeset scans and visually verified character by character against the page images; they are not OCR output taken on trust. Dijkstra's own italics on "Step 1" / "Step 2" are dropped.

- "Problem 2. Find the path of minimum total length between two given nodes P and Q." (p. 270)
- "We use the fact that, if R is a node on the minimal path from P to Q, knowledge of the latter implies the knowledge of the minimal path from P to R. In the solution presented, the minimal paths from P to the other nodes are constructed in order of increasing length until Q is reached." (p. 270)
- "A. the nodes for which the path of minimum length from P is known; nodes will be added to this set in order of increasing minimum path length from node P" (p. 270, definition of set A)
- "B. the nodes from which the next node to be added to set A will be selected; this set comprises all those nodes that are connected to at least one node of set A but do not yet belong to A themselves" (p. 270, definition of set B)
- "Step 1. Consider all branches r connecting the node just transferred to set A with nodes R in sets B or C. If node R belongs to set B, we investigate whether the use of branch r gives rise to a shorter path from P to R than the known path that uses the corresponding branch in set II. If this is not so, branch r is rejected; if, however, use of branch r results in a shorter connexion between P and R than hitherto obtained, it replaces the corresponding branch in set II and the latter is rejected. If the node R belongs to set C, it is added to set B and branch r is added to set II." (p. 270)
- "Step 2. Every node in set B can be connected to node P in only one way if we restrict ourselves to branches from set I and one from set II. In this sense each node in set B has a distance from node P: the node with minimum distance from P is transferred from set B to set A, and the corresponding branch is transferred from set II to set I. We then return to step 1 and repeat the process until node Q is transferred to set A. Then the solution has been found." (p. 270)
- "Remark 1. The above process can also be applied in the case where the length of a branch depends on the direction in which it is traversed." (p. 270)
- "For the branches of set I this is the actual minimum distance, for the branches of set II it is only the minimum thus far obtained." (pp. 270–271, Remark 2)
- "The solution given above is to be preferred to the solution by L. R. Ford as described by C. Berge, for, irrespective of the number of branches, we need not store the data for all branches simultaneously but only those for the branches in sets I and II, and this number is always less than n. Furthermore, the amount of work to be done seems to be considerably less." (p. 271; the original interpolates the bracketed reference numbers "[3]" and "[4]" after Ford and Berge)
- "We consider n points (nodes), some or all pairs of which are connected by a branch; the length of each branch is given. We restrict ourselves to the case where at least one path exists between any two nodes." (p. 269, opening sentences)

## Relevance to this project

- **This is the primary source for the baseline arm of Experiment 1.** The linear-scan O(V²) implementation is not a strawman the report invented to lose a race — it is a faithful transcription of what Dijkstra actually wrote. Step 2 asks for "the node with minimum distance from P" out of set B and specifies nothing more, so scanning set B is the reading of the source. The report can say the naive arm *is* the 1959 algorithm, and cite p. 270 for it.
- **It anchors the report's central thesis directly.** "The data structure IS the algorithm" needs a demonstration that the algorithm proper says nothing about the container, and this paper is that demonstration: the relaxation rule (Step 1) and the settle-in-increasing-order invariant (set A) are fully specified, while the answer to "what do I process next" is left as bare English. Everything the heap changes lives in the gap Dijkstra left open.
- **It establishes that the heap is a data-structure result, not an algorithmic one.** Because the 1959 paper contains no priority queue and no complexity analysis, any O(V²) versus O((V+E) log V) comparison is a comparison of two implementations of *one* algorithm. Pair this with Fredman & Tarjan (1987), who describe their own contribution as an *implementation* of "Dijkstra's algorithm" (their Section 4), and the claim is sourced from both ends.
- **It supports the report's framing of the relaxation loop as the invariant core.** Step 1 is container-agnostic — it is the same edge-scan the report reuses for BFS, naive Dijkstra and heap Dijkstra. Quoting Step 1 verbatim makes the "same loop, different container" argument concrete rather than rhetorical.
- **The single-pair versus single-source distinction is worth one honest sentence.** The report solves SSSP; Dijkstra posed single-pair. Saying so costs nothing and pre-empts a reviewer noticing it.
- **The storage argument foreshadows the report's own concern with constant factors.** Dijkstra's stated reason for preferring his method over Ford's is memory footprint, not asymptotics — a 1959 echo of the report's point that the theoretically better structure is not automatically the better one in practice.

## Cautions

- **Do NOT cite this paper for O(V²), O(n²), or any complexity bound.** The paper states none. It contains no asymptotic notation whatsoever. Write "the method Dijkstra describes admits a straightforward O(V²) implementation" and cite a textbook (e.g. Cormen et al.) or Fredman & Tarjan for the analysis; cite Dijkstra (1959) only for the *method*.
- **Do NOT cite it for anything about heaps, priority queues, decrease-key, or lazy deletion.** None of these words or concepts appear. The paper predates binary-heap Dijkstra (Williams' heapsort is 1964) by five years.
- **Do NOT claim the paper requires or states non-negative edge weights.** It does not. It says only "the length of each branch is given". The non-negativity condition is a later, and necessary, formalisation — Fredman & Tarjan (1987, p. 596 and p. 610) state it explicitly and are the better citation for it. The report must not put that condition in Dijkstra's mouth.
- **Do NOT quote the paper as posing the single-source problem.** Problem 2 is between "two given nodes P and Q" and terminates when Q is settled.
- **Do NOT attribute Problem 1 (the MST algorithm) to the shortest-path discussion,** and be aware Fredman & Tarjan note (p. 611) that this algorithm was actually discovered earlier by Jarník.
- **Do NOT modernise the title spelling.** It is "connexion", not "connection", and the DOI/Crossref record confirms it.
- **Do NOT assert an issue number as fact.** See *Verification.* above: the printed article has none and the authoritative records disagree.
- **The pagination is 269–271, three pages.** Some secondary sources give "269-270"; that is wrong, the article runs onto p. 271 where the references and the Mathematisch Centrum address sit.
